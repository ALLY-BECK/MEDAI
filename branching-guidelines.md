# Регламент работы с Git в проекте MEDAI

В данном документе описаны правила ветвления, защиты ветки `main` и проведения Code Review.

## 1. Структура веток
В проекте используются два типа веток:
- **`main`** — стабильная ветка. Прямой пуш (direct push) в нее запрещен. Все изменения попадают сюда исключительно через Pull Request.
- **`feature/*`** — ветки для разработки новых фич, документации и исправлений.
  - *Пример наименования:* `feature/git-guidelines`, `feature/login-validation`.

## 2. Защита ветки `main`
На GitHub настроена защита ветки `main`:
- Прямые пуши запрещены (`push --force` отключен).
- Для слияния изменений в `main` необходимо создать Pull Request.
- Требуется как минимум одно одобрение (Code Review) от ревьюера.
- Все беседы в PR должны быть разрешены (resolved) перед слиянием.

## 3. Процесс слияния изменений (PR Flow)
1. Разработчик создает локальную ветку `feature/*`:
   ```bash
   git checkout -b feature/your-feature-name
   ```
2. Вносит изменения, делает коммит и отправляет ветку на GitHub:
   ```bash
   git push -u origin feature/your-feature-name
   ```
3. На GitHub создается Pull Request (PR) в ветку `main`.
4. Назначается ревьюер для проверки кода.
5. Ревьюер оставляет комментарии, предлагает правки.
6. Разработчик исправляет замечания, после чего ревьюер одобряет (Approve) PR.
7. PR сливается в `main` с помощью Squash and Merge или Create a Merge Commit.
